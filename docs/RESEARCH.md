Дата: 2026-09-18. Метод: три независимых разведки —
1. **Код**: `этот репозиторий` (7 расширений, 9 069 строк TS) + глобальные `~/.pi/agent/extensions` (6 файлов).
2. **Практика**: 312 файлов сессий (157 родительских + 155 субагентских, 25 518 сообщений), окно 2026-08-26 → 2026-09-18.

## 2. Архитектурные изменения

### 2.1. Телеметрия использования команд — P1 (мета)
Командные расширения невидимы в транскриптах. Решение: каждое расширение пишет `pi.appendEntry("ext_usage", { ext, cmd })` при вызове команды. Дёшево, персистентно в сессию, НЕ попадает в LLM-контекст. Следующее такое исследование станет измеримым.

### 2.2. Consolidation shared/
Сейчас три реализации скролл-UI (ScrollReport ↔ context-inspector/view.ts ↔ prompt-snippets viewport) и два парсера frontmatter (prompt-snippets ≈ subagents/agents.ts). Свести к: `scroll-report.ts`, `frontmatter.ts`, + новый `session-index.ts` (§1.3).

### 2.3. Убрать хардкоды знаний о соседях
`EXTENSION_TOOL_PATHS` (пути между расширениями), `knownToolNames` (дубль встроенных), конвенция `PI_SUBAGENT_SESSION` (prime-protocol ↔ subagents). Заменить шиной `pi.events` / явным реестром — расширения объявляют себя, потребители слушают.

### 2.4. Тесты UI
graph.ts (607 строк — самый большой UI), ResultsView, ReportView, меню snippets — без тестов. Минимум: smoke-рендер компонентов в headless-режиме.

## 3. Идеи новых расширений (по силе доказательств)

### 3.1. session-handoff (auto-resume) — P0
**Доказательства:** 21 промпт-резюме («resume» ×6, «давай продолжим с того места»), ручные md-дампы: «Сохрани все сюда что сделал и что осталось… не хочу терять». Навык session-catchup уже существует — но запускается вручную.
**Механика (API позволяет):** `agent_end`/`session_shutdown` → авто-саммари состояния (задачи, незавершённое, следующий шаг) в `~/.pi/agent/handoff/<project>.md`; `session_start(reason=resume|startup)` → предложить «подхватить с того места». Сквозная боль №1 по частоте.

### 3.2. edit-guard — ✅ РЕАЛИЗОВАНО (2026-09-18, воркер+ревью+фиксер)
`extensions/edit-guard/`: перехват `tool_call` на edit, фазы exact → whitespace → indent → fuzzy (порог 0.85 средняя / 0.6 худшая строка), recovered → подмена oldText сырой подстрокой, ненадёжно → block с диагностикой (строки + сниппеты), телеметрия `edit-guard` (pass/patched/blocked/error). После ревью исправлены: зависание fuzzy на длинных строках (trim префикса/суффикса перед DP + кап 4096 симв/строку — репро 120s → ~4ms), промах needle с завершающим `\n`, юникод-карта встроенного edit, try/catch хендлера с `action:"error"`. Тесты 328/328, smoke зелёный. Не закоммичено — в рабочем дереве вместе с переносом сниппетов и ask-user-question.

### 3.3. /commit flow — P1
**Доказательства:** 17 промптов про разведение коммитов + 11 про push = 28. Навык git-commit-planner существует, каждый раз запускается вручную.
**Механика:** команда `/commit` — анализ diff → план атомарных коммитов → confirm-диалог (`ctx.ui.confirm`) → прогон. Опционально `/commit push`.

### 3.4. browser-verify — P1 (лёгкая верификация)
**Доказательства:** запросы «открой и посмотри» при 10 вызовах browser_*. Пользователь хочет скриншот-проверку как рутину.
**Механика:** один тул `verify_page(url, checks)` поверх существующего browser-синглтона: открыть, снять скриншот + консольные ошибки + сетевые 4xx/5xx, вернуть компактный вердикт. Снижает порог с 8 тулов до 1.

### 3.5. session-digest — P2
**Доказательства:** «проанализируй сессии» — повторяющийся ручной запрос (включая текущую задачу).
**Механика:** `/digest [period] [project]` — прогон анализа по общему индексу (§1.3) через task_batch, отчёт в md. Закрывает и «selective consolidation» (запрос «consolidate --all это опять тащить все сессии из всех 100500 проектов?» — нужен per-project opt-in).

### 3.6. Тест-сниппеты для расширений — P3
**Доказательства:** 11 однотипных промптов-проверок («Скажи только слово: готово» ×6, «Reply with exactly one word…» ×5). Развить prompt-snippets: библиотека готовых проверочных сниппетов + возможно команда /smoke.

## 6. Обратная связь пользователя (2026-09-18)

### 6.1. session-recall — «удобный поиск, в целом годно» ✅
Запускался несколько раз командой. Действия:
- **Переименование** (кандидаты: `session-search` / команда `/find`, `/history`), текущее имя «recall» не самоочевидно.
- Улучшения по-прежнему актуальны: персистентный индекс (§1.3), ранжирование вместо чистого фильтра (BM25-подобный скор, свежее — выше).

### 6.2. session-ledger — «практической ценности не вижу» ⚠ кандидат на opt-in
Причина: стоимость токенов не релевантна на GLM Coding Plan (фикс-прайс); интерес может вернуться при переходе на OpenRouter и т.п. Опасение по «гирькам на весы при каждом запуске»: тяжёлый перечит всех jsonl происходит **только при вызове** `/stats`, не на старте; но модуль грузится всегда вместе с пакетом.
Действия: исключить из дефолтного набора (opt-in через settings / отдельный entry-point), оставить CLI `npm run stats`; перечит всех файлов всё равно чинить общим индексом (§1.3), если ledger останется жив.

### 6.3. session-trace — «пользуюсь часто, но чего-то не хватает» 🔧 P1
- **TUI-вариант не используется: нет консолидации.** Граф не объединяет дочерние субагентские сессии с родительской (155 транскриптов детей лежат отдельно в `sessions/subagents/`). Действия: в TUI-графе подтягивать детей (по `running.json` / `sessions/subagents/` за период сессии) в общую картинку — иначе TUI проигрывает trace-web.
- **trace-web нравится, но нужен дизайнерский проход:** типографика, цветовое кодирование типов ходов/тулов/компакций, компактность карточек, навигация по дереву сессий, статусы воркеров. Действия: UI-ревизия по чек-листу polish (spacing, выравнивание, тёмная/светлая тема), затем фичи.

## 7. Корректировка приоритетов web-направления (по scout-web)
1. **Перемерить отказы DDG** текущей версии `web` (метрика: доля challenge-ответов; можно собирать в `details`/лог) — только по свежим цифрам решать, нужны ли фолбэк-бэкенды (Brave API / SearXNG / Bing).
2. **Кэш web_search + web_fetch** (диск, TTL) — дешёвый, независимый, закрывает частые повторные запросы в рамках задачи.
3. **Закрыть auth-кейс companion**: job на сайте с залогиненной сессией в профиле Chrome (переиспользование вкладок это предполагает, но не подтверждено).
4. **Мелочи web**: jitter/настройки ретраев, укрепить детект challenge (по заголовкам+объёму, не только regex), опционально pin IP против DNS-rebinding.
5. **Companion полировка**: reconnect-окно 30–60s (alarm-rescan уже смягчает), сузить пермишены при публикации.
