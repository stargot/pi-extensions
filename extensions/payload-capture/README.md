# payload-capture

«Перехвати следующий provider-запрос один раз»: расширение для отладки того,
что pi реально отправляет модели. Порт идей из pi-forge (MIT), поверхности API —
по установленной версии `@earendil-works/pi-coding-agent`.

## Команды

| Команда                 | Действие                                                                      |
| ----------------------- | ----------------------------------------------------------------------------- |
| `/payload arm [--save]` | вооружить захват **следующего** provider-запроса (одного)                      |
| `/payload show`         | показать последний захват (redacted JSON) в редакторе                          |
| `/payload clear`        | сбросить состояние (armed/capture) и убрать статус-чип                         |
| `/payload help`         | справка                                                                        |

`/payload` без аргументов показывает краткую подсказку.

Статус-чип в статус-баре: `payload:armed` (accent) → `payload:armed+save`
(warning) → `payload:captured` (success) → снимается через `/payload clear`.

## Приватность (красная линия)

- **Payload никогда не модифицируется.** Обработчик `before_provider_request`
  возвращает `undefined` — запрос уходит модели без изменений.
- **Redaction до хранения.** Захватывается глубокая копия, в которой все поля,
  чьи имена подходят под `/key|token|secret|credential|authorization|api[-_]?key/i`
  (включая `max_tokens` — regex сознательно агрессивный), заменяются на `"***"`.
  Сверх того: data-URI картинок и длинные base64-блобы заменяются маркерами,
  длинные строки обрезаются (12 000 символов), глубина — 8, массивы — 80
  элементов, объекты — 120 ключей, итоговый JSON — ~2 МБ (всё с пометками об
  усечении). Циклические ссылки и JSON-несовместимые значения безопасно
  заменяются маркерами.
- **Дефолт — ничего не сохранять.** Без `--save` захват живёт только в памяти.
- **Запись на диск требует двух условий:** `arm --save` **и** доверенный проект
  (`ctx.isProjectTrusted()`). В недоверенном проекте `--save` игнорируется с
  предупреждением ещё на этапе arm и перепроверяется в момент захвата.
- **Файлы — только вне проекта:** `<agentDir>/cache/payload-captures/<ts>-<model>.json`
  (например `~/.pi/agent/cache/payload-captures/…`). В cwd проекта ничего
  не пишется никогда.

## Тесты

```sh
node --test extensions/payload-capture/test/payload.test.ts
```

Покрывают: redaction credential-полей и лимиты, глубокую копию, arm-once
(второй запрос не захватывается), гейт сохранения (без trusted / без `--save`
файла нет; с обоими — один redacted-файл в agentDir) и снятие чипа.
