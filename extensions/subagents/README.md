# subagents — интерактивные субагенты для pi под Windows (WezTerm/herdr + pwsh)

Спавньте субагентов в собственные терминальные панели, продолжайте работать в главной
сессии — результат придёт steer-сообщением, когда агент закончит. Полностью
асинхронно. Поверхность выбирается автоматически: **herdr**, если pi запущен
внутри herdr (`HERDR_ENV=1`), иначе **WezTerm** (`WEZTERM_PANE`).

Адаптация лучших практик
[amosblomqvist/pi-interactive-subagents](https://github.com/amosblomqvist/pi-interactive-subagents)
(tmux) под текущий стек: **Windows 11 + PowerShell 7 + WezTerm**. Surface-слой
переписан на `wezterm cli`, шелл-обвязка — на pwsh-лаунчеры.

## Инструменты

| Инструмент | Описание |
|---|---|
| `subagent` | Заспавнить субагента в отдельной панели (fire-and-forget) |
| `subagent_message` | Написать по имени: работающему — steer, завершившемуся — resume; `interrupt: true` прерывает текущий ход (Esc) |
| `subagent_cancel` | Отменить работающего субагента: прерывание + cancel-флаг + гарантия «новых tool-вызовов не будет» |
| `subagents_list` | Список доступных определений агентов |
| `task_batch` | Headless-батч без панелей (блокирующий): single / parallel (до 8) / chain с `{previous}` |
| `/subagent <agent> <task>` | Спавн с клавиатуры (с автодополнением имён) |
| `/workers` | Живые headless task_batch-воркеры на всей машине: id, pid, elapsed, задача, session-файл; `/workers kill <id\|pid>` — остановить дерево процессов |
| `/prime on\|off\|status` | Переключатель prime-политики: инжект протокола оркестратора, бюджеты 3/3/3, виджет (см. «Prime policy») |
| `/solo <N>\|off` | Поднять лукап-кап до N / снять solo-блокировки до следующего сообщения |

## Поверхности: WezTerm и herdr

Вся работа с панелями идёт через `mux.ts` — диспетчер с двумя бэкендами и общим
API (split/send/read/list/close). Выбор — `selectBackend` в `mux.ts`, приоритет
у herdr: панель herdr наследует `WEZTERM_PANE` от клиента herdr, но сплитить
через wezterm её нельзя (`pane_id N invalid`) — поверхность принадлежит herdr.

| Операция | wezterm | herdr |
|---|---|---|
| Создать панель | `cli split-pane` (+ `activate-pane` — возвращает украденный фокус) | `pane split --no-focus` (фокус не трогает) + `pane run` с лаунчером |
| Отправить текст | `cli send-text` (bracketed paste + Enter) | `pane run` (текст + Enter одной записью) |
| Прервать (Esc/Ctrl+C) | `cli send-text` (raw-байты, без перевода строки) | `pane send-keys` (`esc` / `ctrl+c`) |
| Доставить steer | `cli send-text` (bracketed paste + Enter) | `agent prompt <paneId> --wait --timeout 15000` (структурированные отказы) |
| Нативный сигнал завершения | — (только вотчер по сайдкарам) | фоновый `agent wait --until done,unknown` рядом с вотчером |
| Переименовать панель (лейбл) | — (no-op) | `agent rename <paneId> <label>` (санитайзер + ретрай `-<id8>`) |
| Прочитать экран | `cli get-text` | `pane read --source recent --lines N` |
| Список панелей | `cli list --format json` | `pane list` (id вида `w1:p2`) |
| Закрыть | `cli kill-pane` | `pane close` |

herdr распознаёт pi нативно (`herdr agent list`) — панели субагентов получают
бейджи working/blocked/idle в его UI без дополнительных телодвижений. Успешно
завершившаяся auto-exit-панель схлопывается сразу после доставки результата
родителю — на обеих поверхностях, WezTerm и herdr, — так что воркспейс
не зарастает мёртвыми панелями.

## Agent-surface (herdr)

Внутри herdr (≥ 0.9.1) расширение использует его agent-surface (`herdr agent …`)
в трёх точках — как дополнение, а не замену собственного вотчера и сайдкаров
(вотчер остаётся источником истины).

Отвергнутые альтернативы:
- fire-and-forget доставка steer без подтверждения — отказ `agent_blocked` происходит до отправки текста, сообщение пропало бы молча;
- poll `agent list` каждый тик / блокирующий `wait` внутри тика вотчера — лишний процесс в секунду либо заморозка вотчера;
- собственный socket-эмиттер blocked-событий herdr — жёсткая связка с внутренним протоколом herdr; в herdr 0.9.1 нативный blocked-эмиттер не работает (`herdr:blocked` не найден).

1. **Доставка steer через `agent prompt`** (ADR-1). `subagent_message` для
   herdr-панели идёт через `herdr agent prompt <paneId> --wait --timeout 15000`:
   herdr отвергает текст ДО отправки, если ребёнок ждёт ввода (`agent_blocked`),
   а `--wait` подтверждает, что ребёнок «увиден working», — ничего не теряется
   молча, как было бы с «напечатать в панель». Любой отказ (`agent_blocked`,
   `agent_prompt_stalled`, `timeout`, `agent_not_found`) превращается в tool
   error с человекочитаемой расшифровкой и советом (`describePromptFailure`);
   worst case — блокировка tool-вызова на 15 с. TARGET — всегда pane id, не имя;
   Esc-ветка (`interrupt: true`) не изменилась. На WezTerm — прежний send-text.
2. **Фоновый сигнал завершения `agent wait`** (ADR-2). Через ~10 с после спавна
   для каждого herdr-ребёнка поднимается один detached-waiter
   `herdr agent wait <paneId> --until done,unknown`; его exit(0) ставит флаг
   `nativeDoneAt`, по которому вотчер (после грейса 5 с, закрывающего гонку
   «pi вышел, лаунчер ещё не записал .done») завершает запись, даже если
   сайдкары потерялись. `done` в herdr = конец хода, поэтому интерактивным
   детям (без auto-exit) waiter не армится — у них «конец хода» не завершение;
   а из живой пробы: после выхода pi запись агента в herdr удаляется
   (`agent_not_found`), поэтому `unknown` тоже считается терминальным.
   CLI из тика вотчера не вызывается вовсе — только чтение флага (нулевой
   оверхед). На WezTerm waiter не поднимается.
3. **Лейблы панелей `agent rename`** (ADR-3). Лейбл `herdrAgentName(name)`:
   lowercase, не-`[a-z0-9]` → один дефис, обрезка 32, начало с буквы, пусто →
   `subagent`; отказ/коллизия → один ретрай с суффиксом `-<id8>` (pane id
   уникален — суффикс уникальный), дальше молча сдаться: вся адресация и так
   по pane id, rename — косметика ради читаемого `herdr agent list`.
   Навешивается лейбл после регистрации агента, не раньше: агентная запись
   появляется, только когда ребёнок pi поднялся, поэтому сплит-тайм rename
   (внутри сплита, до запуска лаунчера) всегда мимо — через ~10 с после
   спавна лейбл перевешивается отложенно (вместе с таймером done-waiter,
   интерактивным детям — отдельный одноразовый таймер), со страховкой
   опросом вотчера до 60 с. `doResume` переименовывает
   переиспользуемую/новую панель тем же отложенным механизмом. На WezTerm —
   no-op.

## Как это работает

```
родитель (pi)                      WezTerm
┌────────────────┐    split-pane ┌────────────────┐
│  subagent() ───┼──+───────────►│ scout   (панель)│
│  работает дальше│              │                 │
│  ◄─ steer ──────┼── .done файл ─│ pi --session …  │
│  (новый ход)    │  + сентинел   │ auto-exit       │
└────────────────┘               └────────────────┘
```

1. **Спавн.** Первый субагент — правый сплит родительской панели (50/50);
   следующие — вниз по правой колонке с процентом `k/(k+1)`, чтобы стопка
   оставалась ровной (`computeStackPercent`). WezTerm всегда фокусирует новую
   панель, поэтому после сплайта фокус немедленно возвращается родителю через
   `activate-pane`; herdr сплитит с `--no-focus` и ничего возвращать не нужно.
2. **Лаунчер.** Панель исполняет `pwsh -NoExit -File <launcher.ps1>`. Скрипт
   выставляет `PI_SUBAGENT_*` env, делает `Set-Location`, запускает
   `pi --session <файл> -e <child-ext> … '@<task.md>'` и по выходе пишет
   сентинел `__SUBAGENT_DONE_<code>__` на экран и код выхода в `<session>.done`.
   Задача передаётся файлом-артефактом (`@path`), а не в командной строке.
3. **Завершение.** Вотчер (тик 1 с) детектит завершение по цепочке «файл →
   сайдкар → экран»: `.done` (быстрый путь), `.exit` (ошибка от child-ext),
   исчезновение панели (краш/закрыли руками), сентинел на экране (fallback).
4. **Результат.** Родитель извлекает из JSONL-сессии ребёнка последнее
   assistant-сообщение + usage (input/output/cost), пишет артефакт для
   `/trace` (`trace:subagents`) и доставляет итог steer-сообщением,
   запускающим новый ход родителя. Итог длиннее лимита обрезается с пометкой
   и путём к полному транскрипту; лимит — env-ручка
   `PI_SUBAGENT_SUMMARY_CHARS`: положительное целое, по умолчанию 8000
   символов, невалидное значение (не число, ≤ 0) молча даёт дефолт. Той же
   ручкой ограничивается вывод каждой задачи `task_batch` (см.
   «Headless-батчи»).
5. **Steer / resume.** `subagent_message` по имени: работающей панели —
   bracketed-paste в живой редактор pi; завершившейся — resume: тот же
   `--session <файл>`, обычно в новой панели (успешная панель закрывается
   сразу после доставки результата); живая панель переиспользуется, если
   ещё не закрыта (например, интерактивный агент). Реестр имён —
   `<artifacts>/<sessionId>/subagent-registry.json`, переживает рестарт pi.
   Обычный steer доставляется на границе следующего хода; параметр
   `interrupt: true` (или автоматика для застывших) сначала шлёт Esc,
   ждёт ~1.2 с и уже потом печатает сообщение — так runaway-ход не глотает
   инструкцию.
6. **Cancel.** `subagent_cancel({ name })` останавливает работающего субагента
   тремя путями сразу: Esc + Ctrl+C в панель (прерывают текущий ход/команду),
   cancel-сайдкар `<session>.cancel` (child-ext опрашивает его раз 500 мс и
   вызывает `ctx.abort()`/`ctx.shutdown()` — единственный канал, достучаться
   до которого runaway-ход не может) и grace-period: если панель через 10 с
   всё ещё жива — force-close. Гарантия: после cancel новые tool-вызовы не
   стартуют (child-ext дополнительно рвёт их в `tool_execution_start`), но
   начатый до отмены tool-вызов может доработать до конца — окончательную
   остановку гарантирует force-close панели через 10 с.
   Итог всё равно приходит steer-сообщением, но с пометкой cancelled и
   предупреждением «считать работу частичной». Завершившегося субагента
   отменить нельзя — только resume через `subagent_message`.

## Headless-батчи (`task_batch`)

Панельный `subagent` — асинхронный и интерактивный. Когда нужны результаты
«здесь и сейчас» в том же ходе, работает `task_batch`: дети запускаются как
`pi --mode json -p` без панелей, инструмент блокируется и возвращает всё одной
пачкой.

- **single** — `{ agent, task }` → финальный вывод ребёнка;
- **parallel** — `{ tasks: [...] }`, до 8 задач, конкурентность 4, вывод каждой
  задачи обрезается до лимита `PI_SUBAGENT_SUMMARY_CHARS` (положительное
  целое, по умолчанию 8000; здесь лимит инфорсится по байтам UTF-8, поэтому
  для кириллицы фактический кап ≈ 4000 символов; невалидное значение молча
  даёт дефолт; та же ручка, что и для результата панельного субагента);
- **chain** — `{ chain: [...] }` последовательно, `{previous}` в задаче
  подменяется выводом предыдущего шага (обрезанным до 16 КБ — промпт едет в
  argv, а командная строка Windows конечна), при ошибке цепочка останавливается.
- **timeoutMs** — таймаут на каждую задачу в любом режиме (по умолчанию
  30 минут; `0` отключает). Зависший ребёнок убивается и возвращается как
  failed — без таймаута он вешал бы инструмент навсегда.

Дети получают сессию под `~/.pi/agent/sessions/subagents/` (появляются
карточками в `/trace`) и нативный denylist `-xt subagent,subagent_message,subagent_cancel,subagents_list` —
панельные инструменты в headless-ребёнке бессмысленны и только жгут контекст.
Запуск разрешает и вложенность: `task_batch` сам себе не запрещён, но глубина
ограничена тремя уровнями — родитель передаёт свою глубину ребёнку через
`PI_TASK_BATCH_DEPTH`, а `task_batch` ребёнка на глубине 3 отказывает спавн
с понятной ошибкой (разгладьте пайплайн или запустите остаток из сессии
помельче). Несуществующий `cwd` задачи ловится до спавна: задача возвращается
как structured failed-результат с точной причиной, остальные задачи батча
продолжают работать.

Windows-нюанс: Node не спавнит `.cmd`-шимы (EINVAL), поэтому раннер парсит шим
`pi.cmd` и запускает `node <dist/bundle/cli.js>` напрямую (`resolvePiEntry`).

Отмена и убийства идут по дереву процессов: на Windows `taskkill /T /F`, на
POSIX — SIGTERM с эскалацией в SIGKILL через 5 секунд (ребёнок, игнорирующий
SIGTERM, будет добит). Убитый ребёнок (Esc, таймаут, `/workers kill`) всегда
возвращается как failed с `stopReason: aborted/timeout` — никогда как ложный
«успех» с пустым выводом. stderr ребёнка хранится хвостом до 64 КБ с маркером
обрезки. Отмена батча не спавнит оставшиеся queued-задачи parallel-режима —
они возвращаются как `cancelled before start`.

## Живой статус

Child-расширение (`subagent-done.ts`, загружается в каждого субагента) пишет
activity-файл: фаза (starting/active/waiting/done), текущий инструмент,
монотонный sequence. Родитель раз в секунду читает его и рисует виджет:

```
Subagents — 2 running
⠋ scout active · grep 42s
▸ worker waiting 2m10s
```

Буллет несёт фазу: ⠋-спиннер — active, красный спиннер — идёт отмена,
⚠ — stalled, иначе ▸.

Если sequence не меняется дольше **5 минут** у auto-exit агента — steer-уведомление
«выглядит застывшим» (с последним замеченным занятием и советами
steer/cancel), при возобновлении — «снова активен». Потоковые дельты
(`message_update`, `tool_execution_update`) считаются активностью через
heartbeat, поэтому здоровая долгая генерация модели ложных срабатываний не
даёт — застывшим считается только по-настоящему молчащий агент. Ставший
застывшим агент при следующем steer прерывается автоматически (Esc),
чтобы сообщение точно доставилось.

## Авто-выход и вложенность

- По умолчанию агенты **автономные** (`auto-exit`): когда ход агента завершён и
  детей в полёте нет, child-ext глушит процесс (`ctx.shutdown()`), и родитель
  получает результат. `auto-exit: false` в frontmatter — интерактивный режим
  (панель живёт до закрытия человеком). Разбор значения строгий: истинность —
  `true/yes/1/on`, ложность — `false/no/0/off` (регистр не важен); любое другое
  значение даёт warning в определение агента и дефолт `true`.
- Субагент может сам спавнить детей: перечислите разрешённых агентов в
  frontmatter (`subagents: scout, researcher`) — ему загрузится тот же
  оркестратор, ограниченный `PI_SUBAGENT_ALLOWED`. Значение `subagents: *`
  разрешает всех известных агентов, включая prime и агентов с
  `dispatch: false` — флаг сужает только dispatch-таблицу prime-политики,
  а wildcard и есть явный opt-in на их спавн (allowlist в ребёнке не
  сужается — ребенок резолвит против собственной discovery); пока дети не
  отчитались, auto-exit родителя-агента подавлен (`runningChildrenCount`).
- Frontmatter агентов: `name`, `description`, `model`, `thinking`, `tools`
  (allowlist → `--tools` + `-ne` в ребёнке), `subagents`, `auto-exit`,
  `readonly`; тело файла — identity, добавляется через `--append-system-prompt`.
  Приоритет: `.pi/agents/` проекта > `~/.pi/agent/agents/` глобальных.
- Общий промпт детей: `<cwd>/.pi/APPEND_SUBAGENT.md`, иначе
  `~/.pi/agent/APPEND_SUBAGENT.md` — добавляется первым `--append-system-prompt`,
  перед identity. Явный `--append-system-prompt` отключает в pi discovery
  `APPEND_SYSTEM.md`, а тот написан для основной сессии (делает оркестратором
  любую сессию с инструментом `subagent`), поэтому у детей свой файл.
- `readonly: true` — ребёнок получает `PI_SUBAGENT_READONLY=1` и
  `-e readonly-guard.ts` (оба пути запуска): `edit`/`write` и shell-команды,
  которые пишут файлы или меняют git, пакеты или удалённое состояние
  (`shared/shell.ts`), блокируются. Это растяжка для модели, а не песочница:
  `python -c`/`node -e` проходят.
- Ребёнок с `tools:` (`child-tools.ts`): `--tools` pi фильтрует и
  инструменты расширений, а `-ne` отключает их discovery, поэтому pane-ребёнку
  явно подключаются guard'ы (`env-guard`, `edit-guard`) и расширения его
  инструментов (`web_search`/`web_fetch` → `web` пакета, `browser_*` →
  `~/.pi/agent/extensions/browser`); агенту с `subagents:` в allowlist
  добавляются pane-инструменты (`subagent`, `subagent_message`,
  `subagent_cancel`, `subagents_list`). Headless-ребёнку (`task_batch`)
  pane-инструменты вычитаются из allowlist — фоновый процесс панели не
  открывает; опустевший allowlist даёт `--no-tools`, а не все инструменты.

## Prime policy

Основная сессия работает как оркестратор («prime»): в system prompt
добавляются тело агента `prime` из объединённого пула (проектный
`.pi/agents/prime.md` переопределяет глобальный), dispatch-таблица ролей
(`| Role | Purpose |`, без колонки Model; опт-аут — `dispatch: false`) и
бюджетная строка. Enforcement — код, а не только промпт:

- **Бюджеты 3/3/3** (константы модуля `prime.ts`): 3 лукапа за ход
  (`read`/`grep`/`find`/`ls`/`glob` + читающие shell-команды), +3 за каждого
  успешно отправленного агента (шаги `task_batch` в режиме `chain` считаются
  диспатчами), кап 3 различных файлов на правки за ход; shell-записи
  (`>`/`>>`, `Set-Content`, `Out-File`, `tee`) идут в тот же кап. Повторное
  чтение уже прочитанного файла бесплатно; счётчики сбрасываются на каждом
  пользовательском сообщении.
- **`/solo <N>`** поднимает лукап-кап до N, `/solo off` снимает все
  блокировки до следующего сообщения.
- **Виджет `⚡ Prime`** (только TUI): бюджет хода, отправленные агенты,
  состояние переключателя; banner при первом сообщении.
- **Переключатель `/prime on|off|status`**, состояние — `<cwd>/.pi/prime.json`
  (контракт `{ "enabled": boolean }`): файла нет → on, молча;
  нечитаемый/невалидный → last-known-good сессии (новая сессия стартует on),
  разовое предупреждение и виджет `unknown (broken .pi/prime.json)`. В
  off-режиме ничего не инжектится и не блокируется, счётчики не ведутся
  (виджет остаётся); `/solo` в off отвечает подсказкой включить prime. Запись
  — только из `/prime on|off` (tmp+rename).
- **Дети никогда не инжектятся и не блокируются**: child-детект (env
  `PI_SUBAGENT_SESSION` → append, совпадающий с телом агента пула →
  `selectedTools`) проверяется до armed-проверки и переключателя в любом
  режиме.
- **Принятый риск ложного main-детекта**: append, в точности совпадающий с
  телом проектного агента, классифицируется как child — main-сессия с таким
  `--append-system-prompt` будет разоружена. Риск осознан и задокументирован
  в [ADR слияния](../../docs/decisions/2026-10-21-prime-subagents-merge.md)
  (таблица рисков, «расхождение child-detect после слияния»).

## Отличия от tmux-оригинала

- **WezTerm вместо tmux**: сплайты с возвратом фокуса, ровная стопка процентами
  вместо `select-layout`, текст — bracketed paste (`send-text`), экран —
  `get-text`.
- **pwsh вместо bash**: лаунчеры — `.ps1` с одинарными кавычками (`''`),
  завершение — через `.done`-сайдкар (быстрее и надёжнее опроса экрана).
- **Нет ask_question** (v1): механика `.ask`-файлов из оригинала не портирована.
- Панель завершившегося агента схлопывается сразу после доставки результата
  (успешного или отменённого; упавшие остаются открытыми для разбора на месте)
  — на обеих поверхностях, WezTerm и herdr: иначе мёртвые shell-панели
  захламляют воркспейс. Resume пересоздаёт схлопнутую панель по требованию.

## Файлы

| Файл | Роль |
|---|---|
| `index.ts` | Оркестратор: инструменты, `/subagent`, `/prime`, `/solo`, вотчер, виджет, реестр, prime-подписки |
| `render.ts` | TUI-рендеры панельных инструментов и карточки `subagent_result` (чистые функции, покрыты `test/render.test.ts`) |
| `subagent-done.ts` | Child-расширение: identity, активность, auto-exit, `.exit`, cancel-поллинг |
| `mux.ts` | Диспетчер поверхностей: выбор herdr/wezterm, общее API для index.ts |
| `wezterm.ts` | Бэкенд WezTerm: все вызовы `wezterm cli` изолированы здесь |
| `herdr.ts` | Бэкенд herdr: все вызовы `herdr pane …` / `herdr agent …` + парсеры JSON-ответов |
| `shared.ts` | Чистые хелперы: сентинел завершения, математика стопки панелей, cancel-сайдкар/interrupt |
| `launcher.ts` | Генерация `.ps1`-лаунчеров (чистая, тестируемая) |
| `agents.ts` | Обнаружение агентов + парсер frontmatter |
| `prime.ts` | Prime policy: инжект протокола, бюджеты, виджет, обработчики `/prime`+`/solo` (чистая фабрика над deps, `test/prime.test.ts`) |
| `prime-protocol.ts` | Чистые функции протокола: dispatch-таблица, бюджетная строка, child-detect, spawn/shell-парсинг (`test/prime-protocol.test.ts`) |
| `activity.ts` | Рекордер активности (ребёнок) и читалка (родитель) |
| `session-read.ts` | Извлечение summary/usage из сессии ребёнка |
| `batch.ts` | Headless-батчи: парсинг JSON-событий, chain/parallel, раннер процессов |
| `registry.ts` | Реестр имён (tmp+rename, переживает рестарты) |
