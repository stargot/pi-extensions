# skill-auditor

Read-only аудит скиллов pi. `/audit` отвечает на вопросы «что реально загрузится», «что модель вряд ли выберет» и «где скиллы перекрывают друг друга» — до того, как молчаливый отказ испортит сессию. Файлы скиллов не двигаются, не правятся и не удаляются: только отчёт и рекомендации.

Парсер frontmatter зеркалит фактическое поведение pi (блочные скаляры `>` / `|` с чомпингом, кавычки, тихий пропуск невалидных), а не спецификацию YAML — находки соответствуют тому, что pi сделает на самом деле.

## Команды

- `/audit` — прогон конвейера для cwd сессии: discovery (четыре локации в порядке pi — см. «Порядок discovery и карта скоупов») → lint → отчёт. В TUI — прокручиваемый вьюер (ScrollReport, как `/handoff`), вне TUI — краткое уведомление со счётчиками.
- `/audit go` — тот же отчёт после confirm уходит модели на семантический разбор: качество роутинга description, пересечения скиллов, кандидаты на перенос из глобала в проектные `.agents/skills` и на `disable-model-invocation`. Модели явно запрещено менять файлы — только рекомендации вида «name → действие → почему».

## CLI

Работает без pi:

```bash
npm run audit                       # текстовый отчёт по текущему каталогу
npm run audit -- --json             # стабильный JSON (для скриптов)
npm run audit -- --dir <cwd>        # проектный контекст discovery
npm run audit -- --agent-dir <dir>  # переопределить ~/.pi/agent
```

Exit code: 0 при любых находках (они advisory), 1 — ошибка окружения, 2 — ошибка аргументов.

## Коды находок

| Код | Severity | Что значит |
|---|---|---|
| `skill-unloadable` | error | SKILL.md не читается или frontmatter не парсится (нет закрытой ограды / пустой description) — pi скилл молча не загрузит |
| `description-too-long` | warning | description длиннее 1024 символов — pi скилл ВСЁ ЖЕ ГРУЗИТ (у самого pi это warning-диагностика, в системный промпт попадает); это нарушение спеки Agent Skills, а не отказ загрузки |
| `name-invalid` | warning | name не соответствует `^[a-z0-9]+(-[a-z0-9]+)*$` или длиннее 64 |
| `name-dir-mismatch` | warning | name не совпадает с именем каталога |
| `name-collision` | warning | то же имя уже занято более ранней локацией (first-wins) — эта копия мертва |
| `broken-reference` | warning | ссылка на файл внутри SKILL.md не разрешается в файл скилла |
| `vague-description` | warning | description без конкретных триггеров («use when» / «используй когда») — слабый роутинг |
| `personal-content` | warning | упоминание чужих домашних путей/имён пользователей |
| `unknown-frontmatter-key` | info | ключ вне спеки (name/description/license/compatibility/metadata/allowed-tools/disable-model-invocation) |
| `orphan-file` | info | файл в каталоге скилла, на который SKILL.md не ссылается |

## Порядок discovery и карта скоупов

Порядок локаций зеркалит pi 0.85.1 (`package-manager.addAutoDiscoveredResources` →
`resource-loader` → first-wins в `loadSkills`):

1. `<cwd>/.pi/skills` — проектные скиллы;
2. `.agents/skills` предков cwd, ближайший первым, до корня репо (каталог с `.git`), он сам включён;
3. `<agentDir>/skills`, где `<agentDir>` = `$PI_CODING_AGENT_DIR || ~/.pi/agent`;
4. `~/.agents/skills`.

Локации передаются в discovery в этом порядке, первое вхождение имени выигрывает:
проектный скилл затеняет одноимённый глобальный (в карте скоупов проигравший помечен
`(shadowed)`, для него же есть находка `name-collision`). Отличие от pi: проектные
локации (1–2) pi подключает только в trusted-проекте, аудитор показывает их всегда.

## Ограничения

- `broken-reference` — эвристика: ссылки на внешние по смыслу файлы (`CLAUDE.md`, `.venv/`, пути других проектов) дают false positive. Код существует, чтобы ловить забытые референсы на собственные файлы скилла; концептуальные внешние ссылки игнорируйте.
- Discovery повторяет поведение pi 0.85.1 в порядке «проект, потом юзер» (см. раздел выше), включая «мертвые» теневые копии в отчёте. Два сознательных отличия: pi гейтит проектные локации флагом trusted, аудитор — нет; pi уважает `.gitignore` при обходе файлов, аудитор инвентаризирует всё → возможен шум `orphan-file` на gitignored-файлах, которые pi вообще не видит.
- Парсер frontmatter — подмножество YAML и не побайтовая копия парсера pi (pi парсит настоящим YAML-парсером поверх `---`-ограды). Расхождения в обе стороны: настоящую YAML-ошибку (табы, сломанные отступы) аудитор может проглотить и НЕ поднять `skill-unloadable`, хотя pi такой скилл отсечёт; и наоборот — файл с оградой `-----` (5+ дефисов) pi распарсит (ищет префикс `\n---`), а аудитор потребует точный `---` и ложно поднимет `skill-unloadable`.
