# skill-auditor

Read-only аудит скиллов pi. `/audit` отвечает на вопросы «что реально загрузится», «что модель вряд ли выберет» и «где скиллы перекрывают друг друга» — до того, как молчаливый отказ испортит сессию. Файлы скиллов не двигаются, не правятся и не удаляются: только отчёт и рекомендации.

Парсер frontmatter зеркалит фактическое поведение pi (блочные скаляры `>` / `|` с чомпингом, кавычки, тихий пропуск невалидных), а не спецификацию YAML — находки соответствуют тому, что pi сделает на самом деле.

## Команды

- `/audit` — прогон конвейера для cwd сессии: discovery (глобал + проектные `.agents/skills` по предкам до корня репо) → lint → отчёт. В TUI — прокручиваемый вьюер (ScrollReport, как `/handoff`), вне TUI — краткое уведомление со счётчиками.
- `/audit go` — тот же отчёт после confirm уходит модели на семантический разбор: качество роутинга description, пересечения скиллов, кандидаты на перенос из глобала в проектные `.agents/skills` и на `disable-model-invocation`. Модели явно запрещено менять файлы — только рекомендации вида «name → действие → почему».

## CLI

Работает без pi:

```bash
npm run audit                       # текстовый отчёт по текущему каталогу
npm run audit -- --json             # стабильный JSON (для скриптов)
npm run audit -- --dir <cwd>        # проектный контекст discovery
npm run audit -- --agent-dir <dir>  # переопределить ~/.pi/agent
```

Exit code: 0 при любых находках (они advisory), 1 — ошибка окружения, 2 — ошибка аргументов.

## Коды находок

| Код | Severity | Что значит |
|---|---|---|
| `skill-unloadable` | error | SKILL.md не читается или frontmatter не парсится — pi скилл молча не загрузит |
| `description-too-long` | error | description длиннее 1024 символов — скилл не попадёт в индекс |
| `name-invalid` | warning | name не соответствует `^[a-z0-9]+(-[a-z0-9]+)*$` или длиннее 64 |
| `name-dir-mismatch` | warning | name не совпадает с именем каталога |
| `name-collision` | warning | то же имя уже занято более ранней локацией (first-wins) — эта копия мертва |
| `broken-reference` | warning | ссылка на файл внутри SKILL.md не разрешается в файл скилла |
| `vague-description` | warning | description без конкретных триггеров («use when» / «используй когда») — слабый роутинг |
| `personal-content` | warning | упоминание чужих домашних путей/имён пользователей |
| `unknown-frontmatter-key` | info | ключ вне спеки (name/description/license/compatibility/metadata/allowed-tools/disable-model-invocation) |
| `orphan-file` | info | файл в каталоге скилла, на который SKILL.md не ссылается |

## Ограничения

- `broken-reference` — эвристика: ссылки на внешние по смыслу файлы (`CLAUDE.md`, `.venv/`, пути других проектов) дают false positive. Код существует, чтобы ловить забытые референсы на собственные файлы скилла; концептуальные внешние ссылки игнорируйте.
- Discovery повторяет поведение pi (глобал `~/.pi/agent/skills`, затем проектные `.agents/skills` от cwd вверх до корня репо, first-wins при коллизиях имён) — отчёт показывает то, что загрузит pi, включая «мертвые» теневые копии.
