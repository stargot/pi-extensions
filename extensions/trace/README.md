# trace

Живой flow-граф сессий pi: ходы агента как карточки, вызовы инструментов как чипы, компакции и смены модели как маркеры на таймлайне. Три формы: расширение pi, автономный CLI и веб-вьюер без зависимостей.

Read-only: только читает session-файлы `~/.pi/agent/sessions/`, ничего не пишет, ничего не отправляет. До переименования внутри этого репозитория расширение называлось pitrace; сессии, записанные старой версией, читаются без ограничений.

## Что рисует

- **Карточка на каждый ход агента**: время, модель, выходные токены, стоимость, длительность
- **Чипы инструментов** под карточкой: имя, сводка аргументов, длительность, `✓ / ✗ / ⠿ running`
- **Превью thinking и ответа** внутри карточки
- **Маркеры таймлайна**: смена модели `⚙`, уровень thinking `✦`, компакция `↻`, ветка `⑂`, метки `⚑`, пользовательские `!`-команды `$`
- **Карточки субагентов** (см. [Субагенты](#субагенты)) со ссылкой на их граф
- **Контекст-дифф по `d`**: кольцевой буфер последних 20 ходов — Δтокены, оценка переиспользования контекста (prefix-ratio) и реальный cache hit-rate чипом, построчный дифф подписей сообщений prev→curr для выбранного хода
- Итоги сессии в шапке: токены, стоимость, бейдж LIVE/replay

## Три формы

| Форма | Что | Как |
|---|---|---|
| **Расширение pi** | `/trace` внутри pi: live-слежение за текущей сессией + replay любой другой | грузится из `pi.extensions` этого репозитория |
| **CLI** | терминальный вьюер всех сессий всех проектов, включая запущенные прямо сейчас | `npm run trace` (см. ниже) |
| **Веб** | агенты (Flow), эры промптов с брошенными ветками (Timeline), состав и дифф контекста (Context), воспроизведение со сжатием пауз | `/trace web` в pi или `npm run trace:web` — браузер откроется сам |

## Команда в pi

```
/trace              текущая сессия, follow за живым хвостом
/trace <file.jsonl> replay любой сессии в темпе её timestamp'ов (×8 по умолчанию)
/trace web [file]   веб-вьюер в браузере (см. «Веб из pi и из консоли»)
/trace on | off     строка состояния над редактором (см. ниже)
```

### Строка состояния

Одна строка над редактором pi, обновляется по событиям агента:

```
◐ T42 ⚒ edit src/auth.ts 0.4s ⠹ · ↑63.5k hit 97% · $1.84 · 2 воркера ●     агент работает
◐ T42 · готово за 2m14s · ↓1.5k · ↑63.5k hit 97% · $1.84 · модель 62% · инстр. 31%
◐ T35 · готово за 40s · ↓900 · ↑38.1k hit 12% ↻ · $1.21                     холодный кэш после компакции
```

Номер хода, идущий инструмент с таймером (или «генерация» со временем запроса), промпт последнего хода и его cache hit (`↻` и цвет предупреждения — кэш холодный, например после компакции), стоимость сессии, число живых task_batch-воркеров; в простое — итог последней эры и доля времени модели и инструментов. `/trace off` скрывает строку, `/trace on` возвращает; выбор хранится глобально в `~/.pi/agent/trace.json` (`{"statusLine": false}`). По умолчанию строка включена.

Аргумент автодополняется живыми task_batch-воркерами (`● live`) и последними 20 сессиями проекта. Сессия живого воркера открывается сразу в live-режиме, с хвоста.

| Клавиша | Действие |
|---|---|
| `↑↓ PgUp PgDn Home End` | скролл (возврат вниз включает follow) |
| `f` | follow за живым хвостом |
| `/` | фильтр по подстроке (чипы, превью, команды) |
| `n` / `N` | следующее / предыдущее совпадение (по кругу; без фильтра — соседний элемент таймлайна) |
| `e` | только ошибки |
| `m` | сводка по моделям: ходы, токены, стоимость |
| `d` | контекст-дифф: таблица последних ходов + дифф контекста выбранного хода (см. ниже) |
| `esc` | сброс фильтров, затем закрытие |
| `q` / `Ctrl+C` | закрыть |

В replay дополнительно: `space` пауза · `←→` перемотка ±5с · `+/-` скорость · `l` в конец (и follow растущего файла) · `r` сначала.

### Контекст-дифф (`d`)

Кольцевой буфер держит снапшоты последних 20 ходов: индекс, время, модель, реальные токены запроса (input/cacheRead/cacheWrite/output) и подписи сообщений контекста — «роль + первые ~80 символов» каждого сообщения (user, assistant, toolResult, bash). Компакция сбрасывает контекст — следующие ходы честно показывают холодный кэш.

Экран режима:

- **Таблица ходов**: `❯ T113 21:52:47 glm-5.3 ↑63.5k Δ+260 ⌁97% hit 100%` — промпт-токены, дельта с предыдущим ходом, чип prefix-ratio (цвет: accent ≥70%, warning ≥40%, error ниже; fg-only) и реальный hit-rate `cacheRead/промпт`, когда провайдер его репортит;
- **Детальный дифф** выбранного хода: `diffLines` (shared/line-diff) над подписями prev→curr с контекстом ±1 строка, разрывы — `⋮`; `+` добавлено, `−` удалено, `~` изменено (до/после с жирными inline-сегментами).

Клавиши режима: `↑↓` — выбор хода (выбор прилипает к последнему, пока не уехали вверх), `PgUp/PgDn/Home/End/f` — скролл, `d`/`esc`/`q` — назад к ленте. Дифф живой: в live-режиме новые ходы сами появляются в таблице.

### Веб-вьюер

Страница строится на том же ядре, что и разбор для pi (`core/`): дерево записей по `id`/`parentId`, активный путь от последней записи, контекст запроса — ровно как его собирает pi (компакция с `firstKeptEntryId`, `context_edit`, `branch_summary`, `custom_message`).

- **Шапка**: имя или первый промпт сессии, `LIVE`/`REPLAY`, стоимость, ↑ промпт и общий cache hit, ↓ выход, разбивка времени «модель / инструменты / ожидание», выбор другой сессии из 40 последних, открытие `.jsonl` с диска, фильтр ходов.
- **Flow** (`1`) — главный агент: состояние, текущий инструмент с таймером, инструменты пути, свёрнутые в `⚒ bash ×9 ✗1`; справа — субагенты из `trace:subagents` и живые task_batch-воркеры.
- **Timeline** (`2`) — эры по промптам со столбиками ходов (высота — выходные токены, цвет — статус) и маркерами `↻ ⑂ ⚑ ✎`; брошенная ветка — приглушённая дорожка со сдвигом сразу после эры, где случилось ветвление, со своим `branch_summary`.
- **Context** (`3`) — состав контекста выбранного хода по ролям (символы, масштабированные к реальному промпту), граница cache hit, cache hit за последние 20 ходов, дифф контекста с прошлым ходом по исходным записям.
- **Инспектор** справа — выбранный ход (промпт эры, рассуждение, ответ, токены, время генерации, вызовы инструментов с длительностью), эра, субагент или воркер с кнопкой «открыть сессию».
- **Низ** — переход по эрам, пуск/пауза, скорость, «сжать паузы» (простои дольше минуты занимают на шкале 5 с), шкала с полосами эр и маркерами, «к live».

Фильтр: `tool:bash`, `err`, `T12..T20`, `model:glm`, остальное — текст промпта, ответа, рассуждения и аргументов. Совпавшие ходы остаются яркими, остальные гаснут; с Flow фильтр переключает на Timeline.

| Клавиша | Действие |
|---|---|
| `1` `2` `3` | вид |
| `[` `]` | соседняя эра |
| `←` `→` | соседний ход |
| `space` | пуск / пауза (с живого края — с начала) |
| `g` | к live |
| `s` | сжать паузы |
| `/` | фильтр |
| `esc` | снять выбор |

Сессия подтягивается раз в секунду — только дописанные байты. Законченная сессия (последняя запись старше 5 минут) при открытии проигрывается целиком за ~5 с; `#end` или `?noplay=1` открывают сразу конец. Вид и «сжать паузы» запоминаются в браузере.

Живые task_batch-воркеры (глобальный running-индекс из subagents, эндпоинт `/workers`, опрос раз в 5 с) — карточки во Flow; «открыть живую сессию» в инспекторе переключает вьюер на сессию воркера (через `POST /load`). Без subagents-расширения карточек воркеров нет.

## Веб из pi и из консоли

```
/trace web              в браузере: текущая сессия
/trace web <file.jsonl> в браузере: любая другая сессия
```

Команда поднимает локальный сервер (`web/serve.ts`, слушает только 127.0.0.1) внутри процесса pi, открывает браузер и останавливает сервер при закрытии сессии pi — сирот на порту не остаётся. Порт — 8787, а если он занят (например, другой сессией pi) — любой свободный, адрес приходит в уведомлении. Повторный вызов не плодит серверы: он переключает файл и открывает вкладку. Старое имя `/trace-web` пока работает с подсказкой про `/trace web` и будет удалено в следующем релизе.

Из консоли:

```bash
npm run trace:web                    # самая свежая сессия на машине
npm run trace:web -- --file session.jsonl
npm run trace:web -- --port 9000 --no-open   # без автозапуска браузера
node extensions/trace/web/serve.ts   # то же самое напрямую
```

Ядро страница берёт с сервера (`/core/*.ts` со стёртыми типами), поэтому `file://` не поддерживается. Перетащить `.jsonl` можно на уже открытую вкладку — тогда живого хвоста нет.

## CLI без pi

```bash
npm run trace:list        # таблица всех сессий всех проектов
npm run trace             # интерактивный выбор → live-follow
node extensions/trace/cli.ts 3          # открыть №3 из списка
node extensions/trace/cli.ts -r 3       # replay с начала (×8)
node extensions/trace/cli.ts file.jsonl # конкретный файл
```

Требует Node ≥ 22.18 и установленных зависимостей репозитория (`npm install` — подтянет peer `@earendil-works/pi-tui`).

## Смоук-рендер без TTY

```bash
node extensions/trace/test/render.ts <session.jsonl> [rows] [--keys=...]
#   --keys="m"          сводка по моделям
#   --keys="/edit\r"    фильтр по подстроке

```

## Субагенты

trace умеет показывать субагентов: дочерние карточки строятся из custom-записей `trace:subagents`, которые автоматически пишет наше расширение [subagents](../subagents/) — оба его инструмента (панельный `subagent` и headless `task_batch`). Транскрипты детей лежат в `~/.pi/agent/sessions/subagents/`, карточки ведут на `/trace <child-session>`. Записи под старым именем `pitrace:subagents` тоже распознаются. Подробности — в [docs/subagents.md](docs/subagents.md).

## Как устроено

pi пишет JSONL-транскрипт каждой сессии в `~/.pi/agent/sessions/<munged-cwd>/` (формат v3: дерево записей с `id`/`parentId`, компакции, итоги веток). trace читает файл инкрементально, нормализует записи в ходы / чипы / маркеры и рисует их: в процессе pi через Extension API, отдельным терминалом через [pi-tui](https://www.npmjs.com/package/@earendil-works/pi-tui) или в браузере без единой зависимости.

- `session.ts` — чистый разбор JSONL в ленту элементов (без зависимостей); плюс per-turn снапшоты контекста в `GraphModel.history`
- `context-history.ts` — кольцевой буфер 20 ходов и метрики диффа (deltaTokens, prefixRatio, changedBlocks, cacheHitRatio) — референс-модель pi-forge, чистый модуль без зависимостей
- `graph.ts` — TUI-компонент (`TraceView`): live/replay, фильтры, мини-карта, режим контекст-диффа по `d`
- `cli.ts` — автономный вьюер на `ProcessTerminal`/`TuiAltScreen` из pi-tui
- `core/` — общее ядро без Node/DOM API: `tree.ts` (дерево записей), `context.ts` (проекция контекста как в pi, состав и дифф), `model.ts` (эры, ходы, ветки, итоги, разбивка времени), `text.ts` (форматирование)
- `web/` — браузерный вьюер: `render.js` (чистые рендеры), `tail.js` (живой хвост), `main.js` (состояние и события); `web/serve.ts` — локальный сервер (статика, ядро, `/session.jsonl`, `/sessions`, `/workers`)

## Тесты

`npm test` в корне репозитория гоняет и юнит-тесты: разбора (`test/session.test.ts`), кольцевого буфера и метрик диффа (`test/context-history.test.ts`). Смоук-рендер — вручную через `test/render.ts` (в том числе `--keys="d"` для режима диффа).
