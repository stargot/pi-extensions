# ask-user-question — структурированный вопрос-тул для pi

Задаёт пользователю ровно один вопрос и приостанавливает выполнение до ответа.
Один инструмент, три режима: свободный текст, одиночный выбор, мультиселект.
Вопрос показывается всплывающим окном в TUI. Грейдинга нет.

Инструмент регистрируется как `ask_user_question`. Вместе с ним в промпт
уходит инструкция: ровно один вопрос на вызов (лучше несколько вызовов, чем
один «пакет»), предпочитать его угадыванию, а если вариант рекомендуется —
ставить его первым и дописать «(Recommended)» к его label.

## Параметры

| Параметр | Обязателен | Заметки |
|---|---|---|
| `question` | да | Ровно один вопрос на вызов |
| `details` | нет | Дополнительный контекст под вопросом |
| `options` | нет | Варианты: `label`, опциональные `value` (по умолчанию = label) и `description`; не задан или `[]` — режим свободного текста |
| `multiSelect` | нет | `true` — допускается несколько ответов на один вопрос |

## Поведение

- **«Other» доступен всегда**, когда есть варианты: пользователь может ввести
  собственный ответ; пункт называется `Other (custom)`, если вариант с именем
  «Other» уже есть среди опций.
- **single-select**: `↑↓` — навигация, `Enter` — выбор, `Esc` — отмена.
- **multi-select**: `space` переключает выбор, `Enter` на сфокусированном
  варианте тоже переключает его выбор, на «Other» — открывает редактор,
  на Submit — отправляет ответ; Submit заблокирован предупреждением, пока не
  выбран хотя бы один ответ; `Esc` отменяет.
- **text**-режим вместо попапа открывает pi-редактор.
- Уже отменённый сигнал возвращает `cancelled`; без интерактивного UI тул
  возвращает `unavailable`, а не зависает.
- Ответы мультиселекта сортируются в результате: выбранные варианты по
  1-based индексу, затем собственный ответ («other»), затем свободный текст.

## Результат

`content` — текстовая строка для модели («User selected: …»,
«User answered: …», «User submitted an empty response», «User cancelled the
question»). `details` — структурированное поле:

| Поле | Что содержит |
|---|---|
| `status` | `answered` / `cancelled` / `unavailable` |
| `question`, `context` | Эхо вызова |
| `mode` | `text` / `single-select` / `multi-select` |
| `answers` | записи `option` (1-based `index`), `other` или `text` |
| `message` | Заполняется при `cancelled` / `unavailable` |

Превью вызова (`renderCall`) показывает вопрос, label вариантов и метку
`[multi-select]`, но никогда — ответ; результат рендерится строками с ✓.

## Совместное использование

Всплывающие окна сериализуются общим мьютексом на `globalThis`
(`__piSharedUiLock`): на экране в каждый момент не больше одного попапа,
два вопроса не перекрываются. Тот же мьютекс могут брать и другие
попап-инструменты, чтобы их окна не перекрывались с этим.

## Тесты

```sh
node --test extensions/ask-user-question/test/ask.test.ts
```

Покрывают: нормализацию опций (trim, `value` по умолчанию = label, пустые
label выбрасываются, `undefined` → `[]`), дизамбигуацию `Other (custom)`,
форматирование ответа для модели (text/other/option), сортировку ответов
(варианты по индексу, затем other, затем текст), `buildResult` для всех трёх
режимов (в text-режиме пустой ответ отличается от содержательного) и
результаты `cancelled`/`unavailable` со статусом и message. Поверх этого —
headless-рендер оверлея через захваченную фабрику `ctx.ui.custom`: матрица
размеров 100×40 / 60×20 / 25×10 × аудит-темы для single-select (вопрос,
пункт «Other», подсказка, без сырого JSON в рендере) и multi-select (Submit
заблокирован warning-строкой «Select at least»). Остаются ручными пунктами
живого чеклиста: text-режим (`ctx.ui.editor`), обрезки хоста, мышь и resize.
