# quiz — градируемый вопрос с вариантами для pi

Градируемый сиблинг [ask_user_question](../ask-user-question/): там, где тот
собирает предпочтение или решение без понятия «правильно/неправильно», `quiz`
задаёт вопрос, у которого заведомо есть правильный ответ, мгновенно оценивает
выбор пользователя (✓/✗) и показывает компактный фидбек — отметку, правильный
ответ и объяснение — и пользователю, и агенту. Только варианты: одиночный
выбор или мультиселект, свободного ввода нет — текст нельзя оценить против
правильного ответа.

Основа — расширение **quiz** автора **Eero Alvar
([amosblomqvist](https://github.com/amosblomqvist))** из
[learn](https://github.com/amosblomqvist/learn/tree/main/extensions/quiz),
перенесено в этот пакет без изменений логики (перебиты импорты).

## Параметры инструмента

| Параметр | Обязателен | Заметки |
|---|---|---|
| `question` | да | Ровно один вопрос на вызов |
| `details` | нет | Дополнительный контекст под вопросом |
| `options` | да | 2+ варианта: `label`, опциональные `value` (по умолчанию = label) и `description` |
| `correctAnswer` | да | Правильный ответ по **`value`** варианта (не по позиции!): строка или массив строк для мультиселекта; value, не совпавший ни с одним вариантом, — жёсткая ошибка |
| `explanation` | да | Почему правильный ответ правильный; раскрывается только после ответа |
| `shuffle` | нет | По умолчанию `true` — варианты перемешиваются перед показом; `false` — когда порядок значим (упорядоченные значения, «всё из перечисленного» в конце) |
| `multiSelect` | нет | `true` — правильно только точное множество: все правильные и ни одного лишнего |
| `web` | нет | `true` — показать вопрос на локальной веб-странице (Markdown, LaTeX, mermaid — см. «Веб-режим») вместо TUI-попапа; учитывается при включённой веб-поверхности (`/quiz-web on`, или `auto` + `web: true`), при сбое сервера — фолбэк на TUI; контракт ответа тот же |

## Поведение

- **«I don't know»** добавляется автоматически и всегда доступен: это не
  настоящий вариант — он не участвует в шаффле, никогда не засчитывается как
  правильный и возвращает отдельный сигнал `dontKnow`, чтобы честное «не знаю»
  не путалось с удачной или неудачной попыткой.
- **Оценка мгновенная**: после выбора — экран фидбека с ✓/✗ по каждому
  варианту, вердиктом и `explanation`; то же попадает в результат агента.
- **note** — постоянное опциональное текстовое поле под вариантами (`tab` из
  списка или клавиша `n` переключают фокус; `tab` в поле возвращает к списку):
  к любому ответу, включая «I don't know», можно приложить заметку; агенту она
  уходит только если непустая.
  Отклонение от апстрима (amosblomqvist/learn, только `tab`): в живой цепочке
  Windows (WezTerm → herdr/ConPTY → pi) `tab` не доходил до попапа в форме,
  которую распознаёт `matchesKey("tab")` pi-tui, поэтому добавлен резервный
  переключатель `n` — печатаемые символы в той же среде до компонента доходят.
- Шаффл выполняется до разрешения `correctAnswer`, так что оценка всегда
  совпадает с тем порядком, который реально видит пользователь.

## Веб-режим

Помимо TUI-попапа вопрос можно показать на локальной веб-странице — там
рендерятся Markdown, LaTeX (`$...$`, `$$...$$`) и mermaid-диаграммы, которых
TUI показать не может. Контракт результата тот же (`status`/`answers`/
`details`), грейд — тот же код.

### Триггеры

- Автор вопроса: параметр `web: true` — ставьте его, когда в вопросе,
  вариантах, контексте или explanation есть LaTeX, mermaid или насыщенный
  Markdown; обычные вопросы быстрее в TUI.
- Пользователь: команда `/quiz-web [on|off|auto]` (сессионная, в памяти,
  по умолчанию `auto`). `on` форсирует веб для каждого вопроса, `off`
  возвращает TUI, `auto` — веб только при `web: true`; без аргумента
  показывает текущий режим. Переключатель старше параметра: `on`/`off`
  форсируют поверхность независимо от `web`.
- Если сервер запустить не удалось — фолбэк на TUI-путь (в headless —
  прежний `unavailable`-результат).
- В превью вызова появляется бейдж `[web]` — только факт поверхности:
  ни URL (в нём токен), ни материала ответа там нет.

### Жизненный цикл и таймаут

- Сервер — in-process, живёт всю сессию (`session_shutdown` гасит его);
  порт эфемерный, поэтому URL меняется от сессии к сессии, а вкладка прошлой
  сессии остаётся в состоянии «ждём вопроса» — это не баг.
- Вкладка одна на сессию: страница поллит `GET /api/v1/state` раз в секунду
  (в скрытом фоне поллинг приостанавливается) и сама подхватывает следующий
  вопрос — вкладки на вопрос не плодятся. Повторное открытие страницы
  показывает текущее состояние (вопрос или фидбек уже отвеченного); фидбек
  остаётся на странице до следующего вопроса.
- Таймаут вопроса: env `PI_QUIZ_WEB_TIMEOUT_MS` в миллисекундах, по умолчанию
  10 минут, `0` — без таймаута; некорректные/отрицательные значения дают
  дефолт. Значение читается ОДИН раз — при старте сервера сессии (им armed-ится
  серверный таймер вопроса), так что смена env в середине сессии не применится
  до новой сессии — это не живая ручка. Истёкший таймаут возвращается как
  `status: "cancelled"` с сообщением, называющим env-ручку.
- Esc (interrupt в pi) во время ожидания — тоже `cancelled`.
- Параллельные веб-вызовы сериализуются собственным FIFO расширения — у
  сервера один активный вопрос. Общий с ask_user_question UI-мьютекс
  веб-путь не берёт.

### Безопасность

- Bind строго `127.0.0.1` и проверка `Host` на loopback
  (анти-DNS-rebinding; общий гард с session-trace вынесен в
  `extensions/shared/loopback.ts`).
- Персерверный случайный токен в URL (`?t=…`), обязателен на `/api/*`
  (сравнение через sha256 + timingSafeEqual); проверка `Origin` на POST
  (CSRF); капа тела POST (64 КБ); CSP на статику; никакой записи на диск.
- Библиотеки рендеринга — с CDN на закреплённых версиях с SRI:
  marked@12.0.2, katex@0.16.11 (с auto-render), mermaid@11.12.1.
  Недоступный CDN или несовпавший SRI — деградация в plain-text с баннером:
  вопрос остаётся отвечаемым, математика «сырая».

### Анти-утечка

До ответа ключ не покидает сервер: `GET /api/v1/state` отдаёт вопрос без
`correctIndices`/`explanation`, грейд считается на сервере, и ключ попадает
в состояние страницы только после принятого ответа — его не видно даже через
devtools. Вариантные `value` тоже не ходят по сети до ответа: страница знает
только `{index, label}` показанного (перемешанного) порядка. Это покрыто
регресс-тестами (payload + реальный `fetch` сервера).

### Headless-бонус

Веб-путь не гвардится `ctx.hasUI` и не берёт UI-лок, поэтому quiz работает
и в headless-сессиях: автозапуск браузера — best-effort (тихий сбой — не
ошибка), а URL гарантированно дублируется в `onUpdate`/транскрипт
(`quiz web: answer at …`), так что открыть страницу вручную можно всегда.
`renderCall` URL не печатает — в нём токен.

### Связь с этапом 2 (lesson-вьюер)

API уже версионирован (`/api/v1/…`), payload декларативен (вопрос внутрь —
ответ наружу), loopback-гард вынесен в общий модуль. Этап 2 — веб-вьюер
целого урока — либо дорастит этот сервер до lesson-сервера, либо поднимет
общий модуль, без переделки контрактов.

## Результат

`content` — текстовый вердикт для модели («answered correctly/incorrectly»,
выбранный и правильный варианты, note, explanation). `details` —
структурированное поле:

| Поле | Что содержит |
|---|---|
| `status` | `answered` / `cancelled` / `unavailable` |
| `mode` | `single-select` / `multi-select` |
| `answers` | выбор пользователя (1-based индексы в порядке показа) |
| `correctIndices` | 1-based индексы правильных вариантов |
| `correct` | `true`/`false`; при `dontKnow` всегда `false` |
| `dontKnow` | `true`, если пользователь выбрал «I don't know» |
| `note` | свободный текст из поля note (если задан) |
| `explanation` | пояснение автора вопроса |
| `options` | все варианты в порядке показа (для транскрипта) |

Превью вызова (`renderCall`) намеренно не показывает ни `correctAnswer`, ни
`explanation`, ни сами варианты (они перемешаются в момент выполнения) —
ответ не утекает в транскрипт до того, как пользователь ответит; это покрыто
регресс-тестом.

## Совместное использование

`quiz` и `ask_user_question` делят общий UI-мьютекс — всплывающие вызовы
сериализуются между собой, два вопроса не перекрываются.
