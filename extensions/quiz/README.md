# quiz — градируемый вопрос с вариантами для pi

Градируемый сиблинг [ask_user_question](../ask-user-question/): там, где тот
собирает предпочтение или решение без понятия «правильно/неправильно», `quiz`
задаёт вопрос, у которого заведомо есть правильный ответ, мгновенно оценивает
выбор пользователя (✓/✗) и показывает компактный фидбек — отметку, правильный
ответ и объяснение — и пользователю, и агенту. Только варианты: одиночный
выбор или мультиселект, свободного ввода нет — текст нельзя оценить против
правильного ответа.

Основа — расширение **quiz** автора **Eero Alvar
([amosblomqvist](https://github.com/amosblomqvist))** из
[learn](https://github.com/amosblomqvist/learn/tree/main/extensions/quiz),
перенесено в этот пакет без изменений логики (перебиты импорты).

## Параметры инструмента

| Параметр | Обязателен | Заметки |
|---|---|---|
| `question` | да | Ровно один вопрос на вызов |
| `details` | нет | Дополнительный контекст под вопросом |
| `options` | да | 2+ варианта: `label`, опциональные `value` (по умолчанию = label) и `description` |
| `correctAnswer` | да | Правильный ответ по **`value`** варианта (не по позиции!): строка или массив строк для мультиселекта; value, не совпавший ни с одним вариантом, — жёсткая ошибка |
| `explanation` | да | Почему правильный ответ правильный; раскрывается только после ответа |
| `shuffle` | нет | По умолчанию `true` — варианты перемешиваются перед показом; `false` — когда порядок значим (упорядоченные значения, «всё из перечисленного» в конце) |
| `multiSelect` | нет | `true` — правильно только точное множество: все правильные и ни одного лишнего |

## Поведение

- **«I don't know»** добавляется автоматически и всегда доступен: это не
  настоящий вариант — он не участвует в шаффле, никогда не засчитывается как
  правильный и возвращает отдельный сигнал `dontKnow`, чтобы честное «не знаю»
  не путалось с удачной или неудачной попыткой.
- **Оценка мгновенная**: после выбора — экран фидбека с ✓/✗ по каждому
  варианту, вердиктом и `explanation`; то же попадает в результат агента.
- **note** — постоянное опциональное текстовое поле под вариантами (`tab` из
  списка или клавиша `n` переключают фокус; `tab` в поле возвращает к списку):
  к любому ответу, включая «I don't know», можно приложить заметку; агенту она
  уходит только если непустая.
  Отклонение от апстрима (amosblomqvist/learn, только `tab`): в живой цепочке
  Windows (WezTerm → herdr/ConPTY → pi) `tab` не доходил до попапа в форме,
  которую распознаёт `matchesKey("tab")` pi-tui, поэтому добавлен резервный
  переключатель `n` — печатаемые символы в той же среде до компонента доходят.
- Шаффл выполняется до разрешения `correctAnswer`, так что оценка всегда
  совпадает с тем порядком, который реально видит пользователь.

## Результат

`content` — текстовый вердикт для модели («answered correctly/incorrectly»,
выбранный и правильный варианты, note, explanation). `details` —
структурированное поле:

| Поле | Что содержит |
|---|---|
| `status` | `answered` / `cancelled` / `unavailable` |
| `mode` | `single-select` / `multi-select` |
| `answers` | выбор пользователя (1-based индексы в порядке показа) |
| `correctIndices` | 1-based индексы правильных вариантов |
| `correct` | `true`/`false`; при `dontKnow` всегда `false` |
| `dontKnow` | `true`, если пользователь выбрал «I don't know» |
| `note` | свободный текст из поля note (если задан) |
| `explanation` | пояснение автора вопроса |
| `options` | все варианты в порядке показа (для транскрипта) |

Превью вызова (`renderCall`) намеренно не показывает ни `correctAnswer`, ни
`explanation`, ни сами варианты (они перемешаются в момент выполнения) —
ответ не утекает в транскрипт до того, как пользователь ответит; это покрыто
регресс-тестом.

## Совместное использование

`quiz` и `ask_user_question` делят общий UI-мьютекс — всплывающие вызовы
сериализуются между собой, два вопроса не перекрываются.
